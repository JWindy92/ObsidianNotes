# My Note-Taking Methodology

This is my personal system for capturing, organizing, and connecting knowledge. It's a living document — revisit and refine it as the system evolves.

---

## The Philosophy

This vault is a **second brain** — a long-term, fully representative record of my thoughts, ideas, research, and experiences. The goal is not a clean, minimal system. The goal is a *useful* one: everything I've ever thought or learned should be findable, connectable, and alive.

Nothing gets deleted. Things that are no longer active get **archived**, not thrown away.

---

## The System: Hybrid PARA + Zettelkasten

The vault is organized in two layers:

**PARA layer** — for things that need a home:
- `Inbox/` — everything lands here first, no decisions at capture time
- `Projects/` — active efforts with a goal and an end date
- `Areas/` — ongoing responsibilities with no end date
- `Resources/` — reference material, saved articles, how-tos, documentation
- `Archive/` — completed projects, inactive areas, anything no longer active

**Zettelkasten layer** — for thinking:
- `Notes/` — atomic ideas, one per note, linked freely across all other folders

**Supporting folders:**
- `Journal/` — daily scratch notes
- `Assets/` — images and attachments
- `Templates/` and `.foam/templates/` — note templates

---

## The One Rule at Capture Time

> **Everything goes to Inbox. No decisions.**

When a thought hits — whether at a desk, in the shower, on a walk — the only job is to capture it. Don't ask where it goes. Don't try to write it perfectly. Just get it out of your head and into Inbox.

Sources that feed Inbox:
- Paper notebook (transcribe during processing)
- Phone (iOS Notes, Obsidian mobile, voice memo transcription)
- Daily note quick captures
- Anything else

---

## The Weekly Processing Session (~20–30 min)

Once a week, go through Inbox with this decision tree:

```
Is this actionable?
├── Yes → Does it belong to an active project?
│         ├── Yes → Move to Projects/
│         └── No  → New project, or file under Areas/
└── No  → Is this worth keeping?
          ├── Yes → Is it an idea/insight? → Notes/ (write as atomic note)
          │         Is it reference material? → Resources/
          │         Is it no longer active? → Archive/
          └── Rarely useful → Archive/ (not delete — preserve it)
```

The goal isn't an empty Inbox. It's a *processed* Inbox — everything touched, nothing forgotten.

## Note Types and When to Use Each

### Daily Note (`Journal/`)
Opened automatically each morning. Use it for:
- Setting a focus/intention for the day
- Quick captures that don't need their own note yet
- Links to meetings or tasks that came up
- Optional end-of-day reflection

### Project Note (`Projects/`)
One per active project. Contains the goal, deadline, next actions, and a decisions log. Links out to related notes and resources rather than containing everything itself.

### Meeting Note (`Projects/` or `Areas/`)
Any meeting worth capturing. Focus on decisions made and action items — not a transcript.

### Literature Note (`Resources/`)
When you read something worth keeping. Write your **reaction** in your own words — not a summary. What was interesting? What would you push back on? What permanent notes should you write from this?

### Permanent Note (`Notes/`)
One idea, clearly stated. Written as if explaining to someone with no context. Always linked to related notes. This is the Zettelkasten layer — where your actual thinking lives, independent of any project or source.

---

## The Linking Habit

Whenever you write or process a note, ask:
> *What does this connect to?*

Add `[[wikilinks]]` to related notes freely. Don't over-think it. The value of this vault compounds over time through connections — a note on decision-making linking to a project, linking to a book note, linking to a personal insight. These connections are the system working.

---

## On Preservation

This vault is meant to be a permanent record. The rule is **archive, not delete**. When something is no longer active or relevant:
- Completed projects → `Archive/YYYY-MM/`
- Old resources → `Archive/`
- Outdated notes → leave them, they're part of the record

The only things worth removing are true duplicates or outright errors.

---

## The Paper Notebook Bridge

Paper is a preferred capture medium at home. The transfer workflow:
1. At the end of the day or during weekly processing, review the notebook
2. Transcribe anything worth keeping into `Inbox/` (or directly to its final home if obvious)
3. Mark transcribed items in the notebook (a checkmark or line through)

*See [[Future Automations]] for ideas on reducing this friction with OCR and iOS shortcuts.*

---

## Principles to Return To

1. **Capture everything, organize later** — friction at capture time kills the system
2. **Archive, don't delete** — the vault is a long-term record
3. **Write in your own words** — a saved link isn't a note; your reaction to it is
4. **Link liberally** — connections are the value, folders are just filing
5. **Process weekly** — Inbox is a buffer, not a destination
6. **Refine the system** — this document should change as the system evolves
